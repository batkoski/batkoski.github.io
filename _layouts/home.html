Approach

Words first. Then pixels. Then code.

  1. Start with the job

    Before I open Figma, I write out who's there, what they're trying to get done, and what they already know. Most design problems get smaller once that's written down.

  2. Name things plainly

    If people wouldn't say it out loud, it shouldn't be in the UI. I'd rather call it Files than make up a new word for files.

  3. Build it to find out

    When I can build it myself, I do. A working page settles questions a mockup can't, and it usually gets there faster.
